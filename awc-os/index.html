02 · AWC-OS · The demonstration

Not every answer was allowed.

Developed by Al-Baseera (البصيرة) and presented at the AMAD 2026 FinTech Hackathon (Alinma Bank × Tuwaiq Academy).

A fine-tuned model writes a program for each financial question; a separate, deterministic engine runs it, refuses it with a Sharia-compliant alternative, or blocks it. In the film, a request for a savings account paying 5% interest is refused before it reaches the customer, and a halal alternative is offered; a zakat question is computed exactly, SAR 4,226.25, and its trace is opened step by step. One savings prompt produced an over-promising takaful program: its assertion failed, the engine returned BLOCKED, and no rule was relaxed to force a successful demonstration.

A hackathon demonstration: the MVP runs on an evaluation machine, not on deployed hosting, and the iPhone demo runs offline. No deployment is claimed.

How it decides

question + financial state
  → fine-tuned model (live synthesis, greedy decoding)
  → FSL program
  → Swift fsl-cli → AWCOSCore   (canonical interpreter — same engine as the iPhone app)
  → EXECUTED · REFUSED · BLOCKED   + replayable receipt

The browser MVP and the native iPhone application execute generated programs through the same Swift AWCOSCore engine — the rule layer is not reimplemented and not simulated.

EXECUTEDThe program parsed, every predicate and assertion passed, execution completed.
REFUSEDThe request violated a constitutional predicate; a policy decision — refused, with an attested Sharia-compliant alternative.
BLOCKEDThe proposal failed an assertion or could not establish execution conditions; no result is authorized.

Measured failure retained: one savings prompt generated an over-promising takaful program whose assertion failed; the engine returned BLOCKED. No rule was relaxed and no output was rewritten to force a successful demonstration — the prompt remains reachable through free-form input.

AWC-OS does not measure success by whether the model always produces an answer; it measures success by whether unauthorized answers fail safely.

The demonstration paths

  1. Zakat — exact numerical execution (SAR 4,226.25): correct computation
  2. Portfolio audit — attestations and execution trace: explainability
  3. Planning — job-loss cashflow scenario: forward recommendation
  4. Adversarial — constitutional refusal with compliant alternative and AAOIFI citation: constitutional refusal

The live MVP runs on a real evaluation machine, not on always-on cloud hosting: live synthesis from the fine-tuned model (4–8s per question), executed through the same deterministic Swift engine that runs on the iPhone. The demo runs offline on an iPhone 16 Pro Max. A live session can be requested through the contact page.
