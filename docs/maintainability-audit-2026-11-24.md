## Priority 1

### 1. Publication does not enforce the documented browser gate

The release procedure requires both browser receipts before publication. The publisher runs `verify.sh`, suppresses its standard output, and builds the artifact if verification exits zero. The validator intentionally exits zero for a structurally valid record, even when the mandatory pre-publication checks have expired. The working candidate demonstrated both results in the same successful run. Its dirty state separately blocks publication today. A clean, admitted commit with the same missing evidence could advance. [Release procedure](architecture.md#integrity-deployment-and-offline-behavior) · [publish.sh, line 37](../publish.sh#L37) · [Validator exit, line 774](../tools/vaic_validate.py#L774)

**Change and acceptance.** Give the publish entry point an explicit pre-publication verdict from the existing validator. Require `projection == VALID` before the remote update, print the obligation IDs that need attention, and keep the origin check after Pages serves the artifact. A clean candidate missing either required browser receipt must stop before any push. A candidate with complete projection evidence must be able to proceed while its first origin observation is pending.

### 2. A failed local build can erase the previous artifact or an unrelated directory

`deploy.sh` accepts an inherited `DIST` and recursively removes that directory before checking that all sources exist. Its intended use is an isolated test output. Direct invocations also use it, so an inherited path can direct cleanup outside the site. Even with the default destination, a missing input or failed copy leaves a partial rebuild and discards the previous good artifact. The publisher clears `DIST`, which limits the first risk on that entry point. This finding follows from the order of operations. [deploy.sh, lines 16–32](../deploy.sh#L16) · [Publisher’s override handling](../publish.sh#L28)

**Change and acceptance.** Preflight the manifest, build and verify in a fresh owned directory, and replace the designated artifact only after success. Keep the test override explicit and reject an existing unowned destination before cleanup. Test that a missing source preserves the previous good output and that a destination containing unrelated files is refused intact.

### 3. Concurrent publications can silently overwrite a newer release

The publisher fetches `gh-pages`, saves that commit under a local rollback branch, then force-pushes unconditionally. If another operator publishes between the fetch and the push, the later push can overwrite a release the first operator never saw. Its saved rollback points to the older commit. Operators using the same checkout also share the mutable `dist/` directory. The documented recovery command force-pushes too, and its rollback ref resides on the publishing machine. No concurrent production push was attempted. [publish.sh, lines 43–55](../publish.sh#L43) · [Recovery procedure](operations.md#how-to-restore-it)

**Change and acceptance.** Give each publish its own output directory. Bind the remote update to the exact fetched commit ID with an explicit Git lease, and make the deployed and preceding artifact IDs retrievable from another machine. Apply the same lease to recovery. In a disposable remote, the second of two publishers starting from the same tip must stop, and a second checkout must be able to restore the intended bytes. [Git push lease semantics](https://git-scm.com/docs/git-push)

## Recommended order

1. **Make a release safe to attempt twice.** Enforce the pre-publication verdict, isolate the output, guard the destination, bind the push to the observed remote tip, and prove recovery from a second checkout. Retain manual publication authority.
2. **Make the evidence independently reproducible.** Run the existing verifier on a clean full-history checkout. Address the recorder’s provenance and interruption handling, then align media-range evidence and asset input checks with their claims.
3. **Reduce the cost of routine edits.** Correct the onboarding and release guide first. On the next change to contact or media behavior, consolidate that specific duplication and replace its source-text tests with behavior tests. Preserve the served routes, accessible fallback, language ownership and historical evidence links.

The publisher checks that served files are tracked, the validator enforces scope and severity together, the kernel test exercises refusals directly, subject truncation is code-point-aware in both contact pages, and the stylesheet has a short-viewport close layout. These are source-level follow-ups. The original viewport and every historical experiment were outside this rerun.
